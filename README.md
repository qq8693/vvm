# 我的小店 · 静态商品展示网站（中英双语 / 外贸可用）

一个**不需要服务器、不需要买域名、完全免费**的商品展示网站。  
支持**中英文一键切换**，适合外贸。商品图片和文字全部装在一个数据文件里，  
改完商品重新上传这一个文件就能更新。

---

## 一、文件夹里都有什么

```
shop/
├── index.html          ← 网站主页（客户看的就是这个）
├── admin.html          ← 商品管理工具（双击用浏览器打开，改商品用）
├── scrape_tool.py      ← 商品采集工具（从上家店铺一键采集图文）
├── 启动采集工具.bat      ← 双击这个启动采集工具
├── assets/
│   ├── style.css       ← 网站样式
│   ├── app.js          ← 网站逻辑（含中英文案）
│   └── translate.js    ← 中→英离线词典（想改译文就改这里的词表）
├── data/
│   ├── products.js     ← 商品数据 ★ 最常更新的文件
│   ├── terms.json      ← 上面那本词典导出的副本，给采集工具用（不用手改）
│   └── demo-data.js    ← 示例数据（管理工具「恢复示例数据」用）
├── images/             ← 商品图片
├── _tools/             ← 小脚本（导出词表等），跟网站无关，上传时可以不带
└── README.md           ← 本文件
```

> `_tools/` 文件夹是开发用的，跟网站无关，上传时可以不带。

## 二、先本地看看效果

1. 双击 `index.html`，浏览器会打开网站（能看到示例商品）。
2. 右上角点 **English / 中文** 可以切换语言。
3. 双击 `admin.html`，这是管理工具，可以增删改商品、改店名、填中英文文案。
4. 在管理工具里改完，点左下角 **「在浏览器里预览网站」** 可以先看效果，满意再上传。

## 三、从上家店铺一键采集商品（推荐）

上家发你一个商品链接，你不用再手动存图、复制文字：

1. **双击「启动采集工具.bat」**，浏览器会自动打开一个操作页面
   （黑色命令行窗口不要关，关了工具就停了；第一次运行需要电脑装过 Python）。
2. 把上家的**商品链接**粘进去，点 **开始采集** —— 图片和文字说明会自动抓下来。
3. 检查一下自动填好的内容，主要就补三样：
   - **价格**（上家不公开价格，必须自己填）
   - **品类**（一般会自动选好，不对就手动改）
   - 标题 / 描述里删掉不要的广告语
4. **英文栏会自动翻好**（见下面「自动翻译」），过一眼就行，不顺的地方直接改。
5. 图片默认全选，不想要的点一下就取消。
6. 点 **写入 products.js** —— 搞定，接着可以粘下一个链接继续采。

采完的商品在 `admin.html` 里也能看到（打开管理工具时如果提示
「products.js 比本地新」，点 **载入文件数据** 即可同步过来）。

### 自动翻译（采集完自动出英文）

采集完中文标题和描述后，工具会**自动翻成英文**填进下面的英文栏，你只管改。

- **纯本地词典，不联网、不花钱、不上传你的商品文案**，词表就在 `assets/translate.js` 里。
- 译文上面的小字会显示 **覆盖率**（比如「覆盖 93%」）：
  - 覆盖率越高越靠谱；低于 70% 会顺便列出**没收录的字**，方便你补。
  - 觉得翻得不对就改中文或直接改英文；改完点 **重新翻译** 可以重来一次。
- **你自己改过的英文不会被自动覆盖**：只要动过英文栏，之后再改中文也不会冲掉你的译文，
  想强制重翻就点 **重新翻译**。

**想让译文更好？补词表就行**（不用改代码）：

1. 打开 `assets/translate.js`，找到 `var TERMS = [` 那一段，按 `['中文', 'English'],` 的格式加词。
   > 词越**长越优先**，所以「儿童马丁靴」会优先于单独的「儿」。
   > 想让某个词直接消失（比如语气词），把英文写成空串：`['的', ''],`。
2. 保存后运行一次 `_tools/export_terms.py`（用来把词表同步给采集工具），
   或者直接删掉 `data/terms.json`，工具下次启动会自动重新生成。
3. 重新启动采集工具即可生效。

> 上家如果设置了「仅好友可见」，采集会失败并提示，这种情况只能手动存图上传。

**两种图片方式**：

| 方式 | 优点 | 缺点 |
|---|---|---|
| 下载到本地（默认） | 网站加载快、不依赖上家；上家删图也不影响 | 上传时要连 `images` 文件夹一起传 |
| 直接用上家原图 | 只需上传 `products.js` 一个文件 | 上家删图 / 防盗链时你的图会挂 |

> 上家如果设置了「仅好友可见」，采集会失败并提示，这种情况只能手动存图上传。

## 四、中英文双语怎么填

- 网站右上角的「**中 / EN**」按钮可以开关，客户随时切换，网站会记住每个访客的选择。
- 管理工具里，每个文字字段都有**中文栏 + 英文栏**：
    
  商品名 / 描述 / 单位 / 尺码 / 颜色 / 参数 / 标签，以及分类名、店名、公告、首屏文案、联系方式。
- **英文栏留空时，英文界面会自动显示中文**，不会出现空白。所以可以先上线再慢慢补。
- **不想一个个手翻**：在管理工具里打开任意商品，编辑框上方有一排翻译按钮 ——
  **翻译标题** / **翻译描述** / **翻译标题+描述**，点一下就把中文一键翻成英文
  （和采集工具用的是**同一套本地词典**，不联网）。翻完可以直接改，改过的不会被覆盖。
- 商品列表里带「**缺英文**」黄标的，就是还没填英文名的商品。
- 英文价格：在「店铺设置 → 语言与货币」里填汇率和货币符号。
    
  例如填 `0.14` 和 `$`，¥899 会显示成 $125.86；填 `1` 则表示英文界面也显示同样的数字。
- **外贸优先填这几项**：商品英文名、英文描述、分类英文名、店铺英文名、WhatsApp 和邮箱。
- 联系方式会自动显示成英文标签（WeChat / Phone / Email / WhatsApp），WhatsApp 客户点一下就能打开聊天。

## 五、第一次发布到 GitHub（约 10 分钟，免费）

1. 打开 [github.com](https://github.com) 注册一个账号（免费），记住**用户名**。
2. 登录后点右上角 **＋** → **New repository**。
3. 仓库名填一个英文名，比如 `myshop`；可见性选 **Public**；点 **Create repository**。
4. 进入仓库后点 **Add file** → **Upload files**，  
   把 `index.html`、`admin.html`、`assets`、`data`、`images` 这几项**一起**拖进去，拉到底点 **Commit changes**。
5. 在仓库里点 **Settings** → 左侧菜单 **Pages**。
6. **Source** 选 `Deploy from a branch`；**Branch** 选 `main`，目录选 `/ (root)`；点 **Save**。
7. 等 1～3 分钟刷新页面，顶部会出现网址，形如：
   ```
   https://你的用户名.github.io/myshop/
   ```
   把这个网址发给客户就能看了。手机打开也没问题（网站是响应式的）。

> 打不开 / 404？等 2 分钟再刷新。第一次部署偶尔会慢一点。

## 六、以后怎么更新商品（日常操作，2 分钟）

1. 双击打开 `admin.html`，在「商品管理」里添加 / 修改 / 删除商品。
2. 点左侧 **导入 / 导出** 里的 **下载 products.js**。
3. 登录 GitHub → 进入你的仓库 → **Add file** → **Upload files**，  
   把刚下载的 `products.js` 拖进去（会提示同名覆盖，确认即可）→ **Commit changes**。
4. 等 1～2 分钟，刷新你的网站，新商品就出现了。

> 用采集工具加的商品：**上传 `products.js` + `images` 文件夹里新增的图片**（图片文件名以商品编号开头，只传新增的就行）。
> 用管理工具手工加的商品：只需要上传 `products.js` 一个文件（图片自动打包在里面）。
> 上传前留意管理工具「导入 / 导出」页显示的数据大小，**GitHub 网页上传单个文件不能超过 25 MB**，
> 超了就用采集工具里的「一键瘦身」把内嵌图片抽出来。

## 七、关于图片

- 用采集工具加的商品，图片默认自动压缩后存到 `images/` 文件夹（900px / 中等画质，单张约 100 KB），网站直接引用文件，速度快。
- 在管理工具里上传图片，会自动压缩成合适的大小再**打包进数据文件**，不需要单独传图片文件。
- 推荐设置：最长边 **1200px**、画质 **0.80**。单张图大约 100～200 KB，几十件商品完全没问题。
- 商品特别多（100 件以上）想让网站更快，可以在添加图片时改用**路径方式**：  
  把照片文件放进 `images/` 文件夹一起上传，然后添加图片时填 `images/照片名.jpg`。

## 八、常见问题

**Q：改了商品，网站没变化？**  
确认已经 Commit → 等 1～2 分钟 → 手机浏览器强制刷新（或清缓存）。

**Q：能直接收款下单吗？**  
不能，纯静态网站没有后端。常规做法是：客户看中 → 点「联系店主」加微信 / WhatsApp / 发邮件 → 你手动收款发货。  
管理工具里的「店铺设置」可以填 WhatsApp、邮箱、微信号、电话和微信二维码。

**Q：换电脑了数据还在吗？**  
管理工具的数据存在浏览器本地。换电脑前先导出 `products.js` 存好，  
在新电脑上用「导入」功能选这个文件即可恢复。

**Q：想要自己的域名？**  
买个域名（一年几十块），在 GitHub Pages 的设置里填 Custom domain，再到域名商那里加一条解析。  
想弄的时候再研究，不着急。

**Q：数据文件太大了会怎样？**  
GitHub 网页上传单个文件上限 25 MB。采集工具首页会显示当前大小，
如果「内嵌」图片太多导致超限，点采集工具里的 **「把内嵌图片转换成文件」** 一键瘦身
（转换前会自动备份成 `data/products.js.bak`），然后再上传时把 `images` 文件夹一起传上去。

**Q：自动翻译要联网吗？要收费吗？会被上家看到我的文案吗？**  
都不用。词表就放在你本机的 `assets/translate.js` 里，翻译在本地完成，
不进任何服务器、不调任何接口、不花一分钱，商品文案也不会外传。

**Q：翻译翻得不准怎么办？**  
先看译文上面的**覆盖率**：低于 70% 说明词表认识的字太少，
把「没收录的字」补进 `assets/translate.js` 的 `TERMS` 就行（README 第三章有写法）。
覆盖率很高但还是不顺的句子，直接在英文栏手改 —— 改过的不会被自动覆盖。

**Q：已经上架的老商品能补翻译吗？**  
可以。打开 `admin.html`，进任意商品的编辑框，点上面的 **翻译标题+描述** 一键补上英文。

## 九、技术说明（给以后维护的人）

- 纯静态，零依赖，无构建步骤，任何静态托管都能跑（GitHub Pages / Vercel / Netlify / 任意 Nginx）。
- 网站读取 `data/products.js`（`window.SHOP_DATA`），也兼容 `data/products.json`。
- 双语：每个文字字段都有一个带 `En` 后缀的英文版（`name` / `nameEn`、`description` / `descriptionEn`…），
    
  英文留空时英文界面自动回退显示中文。
- 语言开关与价格换算在 `shop.i18n`：`enabled` `default` `currency.{zh,en}` `rate`。
- 商品字段：`name` `nameEn` `category` `price` `originalPrice` `unit` `unitEn` `images[]`
    
  `description` `descriptionEn` `sizes[]` `sizesEn[]` `colors[{name,nameEn,hex}]`
    
  `specs[{k,kEn,v,vEn}]` `tags[]` `tagsEn[]` `stock` `soldOut` `hidden` `featured` `order` `createdAt`。
- 联系方式里 `whatsapp` 会自动生成 `https://wa.me/` 链接。
- 主题色在 `shop.theme` 里，改了会自动生效。
- 采集工具 `scrape_tool.py`：本地起一个 127.0.0.1 网页服务，解析上家链接里的店铺号和商品号，
  调 `https://<店铺域名>/commodity/view` 接口拿标题、图片和标签（先访问商品页取游客 token cookie），
  再把商品追加进 `data/products.js`；图片下载时用腾讯云 CI 参数（`imageMogr2`）在对方服务器上完成缩放压缩。
- 数据文件每次被写入都会先备份成 `data/products.js.bak`。

### 离线翻译（`assets/translate.js` + `data/terms.json`）

一套词表，两个地方用，保证网页端和采集工具译文一致：

| 文件 | 作用 |
|---|---|
| `assets/translate.js` | **词表源头**（人改这里）。浏览器里挂 `window.TT`：`TT.title()` `TT.desc()` `TT.text()` `TT.coverage()` |
| `data/terms.json` | 由 `_tools/export_terms.py` 从上面的 js 抽出来，给 Python 端复用。**不用手改** |
| `scrape_tool.py` 的 `translate_*()` | Python 版实现，逻辑与 js 对齐（见下） |

翻译流程（两边一致）：

1. **整句规则优先**：`apply_rules()` 先跑正则，处理「材质：牛皮」→`Material: cowhide`、
   「码数26-35」→`Sizes: 26-35`、「24年当季」→`2024 season` 这类整句写法。
2. **正向最大匹配**：按词长**从长到短**扫描，命中就替换 —— 长词优先，所以
   「儿童马丁靴」会整体命中，不会碎成「儿」+「童」+「马丁」+「靴」。
3. **没收录的中文字直接跳过**，避免出现中英混排；英文/数字/emoji 原样保留。
4. **收尾**：`norm_en()` 统一标点与空格（`. Logo`→`.Logo`、`Material:  x`→`Material: x`），
   `_dedupe()` 去掉相邻重复词（`Bag Bag`→`Bag`），
   标题再走 `_title_case()`（品牌保持原样、小词小写），描述每行首字母大写。
5. **覆盖率**：`translate_coverage()` 算出认识多少字、哪些没收录，前端显示成「覆盖 93%」。

想换效果**只改词表**即可：

- 加词：在 `TERMS` 里加 `['中文', 'English'],`；想让某个词消失就把英文写空串 `['的', ''],`。
- 加整句规则：改 `_RULES`（Python）和 `RULES`（js）两边。
- 改完运行 `_tools/export_terms.py` 重新导出 `data/terms.json`（或在 `export_terms.py` 里删掉该文件让工具自建）。
